# Technical Design

## Purpose

基于现有代码库，产出最小可行的技术方案。

## Process

1. 检查当前实现。
2. 识别相关模块。
3. 识别现有模式。
4. 确定最小可行改动。
5. 识别依赖。
6. 识别风险。
7. 定义验证方式。

## Principles

```text
现有模式 > 新抽象
小改动   > 大重构
复用     > 新依赖
```

## Output

- 当前架构
- 建议改动
- 受影响组件
- 实现步骤
- 验证计划
- 风险

## 为什么有效

「最小可行改动」是可验证的原则：改动越小，越容易验证（Leader 复跑 / Tester 回归），回归风险越低。
